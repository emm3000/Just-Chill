# E07-01 — Clear the `:domain` and `:data` baselines

**Epic:** [E07 — baseline burn-down](../epics/E07-baseline-burndown.md)

## Done when

- [ ] `baseline-domain-main.xml`'s single `UnsafeCallOnNullableType` is gone, fixed in code
- [ ] `baseline-data-main.xml`'s 6 entries are gone: `InjectDispatcher` on `Dispatchers.android.kt`,
      and `TooManyFunctions` plus four `UnnecessaryNotNullOperator` on `TransactionMappers.kt`
- [ ] the four `!!` in `resolveCategory` are gone with its all-or-nothing contract intact: any one
      missing field still yields a null category, never a partial one
- [ ] `baseline-data-iosMainSourceSet.xml`'s 2 `FunctionSignature` entries are gone
- [ ] `baseline-data-androidDeviceTestSourceSet.xml`'s 14 entries are gone
- [ ] every baseline touched is regenerated by its `detektBaseline*` task, never hand-edited; any
      surviving entry is named in the closing commit with the reason it survived
- [ ] no threshold in `config/detekt/detekt.yml` is relaxed and no new `@Suppress` is added
- [ ] `./gradlew qualityGate --rerun-tasks` and `./gradlew assembleDevDebug` both pass

## Context

`TransactionMappers.kt` sits on the read path every transaction list renders. The four `!!` are not a
schema problem: `resolveCategory` already guards every field but hoists the check into
`val allFieldsPresent`, and smart cast cannot see through a boolean in a variable — no `.sq` change
is in scope. Its `TooManyFunctions` is the costly one: a file-level entry is amnesty at any size
(E07), so the file wants splitting by responsibility. If no split reads better than the file does
today, say so and keep the entry rather than forcing one.

`data-androidDeviceTestSourceSet` is instrumented source that only runs on a device; its 14 entries
are formatting and carry no behavior risk.
