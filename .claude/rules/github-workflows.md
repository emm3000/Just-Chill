# CI, release and the gate

- `./gradlew qualityGate` is the gate, invoked by the pre-push hook and the three build workflows (`buildDev`, `uploadApk`, `uploadRelease`; `probeStorageRls` runs no Gradle). The plugin `build-logic/.../QualityGateConventionPlugin.kt` matches `detektMain`/`detektTest`, `:data`'s instrumented compile and `verifySqlDelightMigration`, and names `:build-logic:convention:test` explicitly (an included build is unreachable by task-name matching). It also registers `checkModuleBoundaries` (ADR 015's allowed edges, read off each module's own declared project dependencies) and `checkComposeFreeViewModels` (no `androidx.compose` import in a `*ViewModel.kt` or `*UiState.kt` under the module's `src/`; `:androidApp` is exempt as the composition point). `justchill.android.library` and `justchill.jvm.library` add the module's unit tests; only `:androidApp` names its own, because its flavors live in its build file: `testDevDebugUnitTest`, `lintDevDebug`, and `qualityGate { detektTasks }` set to `detektDevDebug`, `detektDevDebugUnitTest` and `detektProdRelease`, which replace the aggregates and cover every source set once. Never gate on plain `./gradlew detekt`: it covers strictly less.
- Triggers. `buildDev` (PR to `trunk`): a `changes` job runs `git diff --name-only` against the base; the required check `quality-gate` is skipped (counted as passing) only when the PR touches `**/*.md`, `docs/**`, `.claude/**`, `scripts/justchill-*` or `.github/dependabot.yml` alone, and runs whenever `changes` did not succeed. It runs `qualityGate assembleDevDebug`, plus `assembleProdRelease` when the PR touches `build-logic/**`, `gradle/**`, `*.gradle.kts`, `gradle.properties`, `*.pro`, `androidApp/**` or `.github/**`. `uploadApk` (every `trunk` push): the full gate, both builds and Firebase App Distribution; a newer push cancels the running one. `uploadRelease` (tag `v*.*.*` or manual): gate, release lint, bundle, Play draft. Report upload paths are `**` globs, never module names.
- Branch protection is `strict: false`, so the `uploadApk` gate is the only net for semantic conflicts between PRs green on their own. Never drop it.
- The Crashlytics mapping upload runs only with `-Pjustchill.crashlyticsMappingUpload=true`, which `uploadApk` passes on `trunk` and `uploadRelease` on a release tag or a manual dispatch from `trunk`. PRs, Dependabot and local builds never upload.
- Third-party actions are pinned to a commit SHA on purpose: they hold the signing and Play/Firebase credentials, and a floating `@v1` can be repointed upstream. Do not tidy them into tags; dependabot proposes bumps. GitHub's own `actions/*` stay on tags.
- `versionName` is `git describe --tags --abbrev=0 --match "v[0-9]*"`. The filter is load-bearing (the repo carries non-release tags; builds once shipped `versionName = "pre-kmp"`), and `--abbrev=0` means it is always the bare tag, so `versionCode` is what names a build. Same filter in `/release`.
- A tag push does not ship. `uploadRelease.yml` uploads the AAB to the alpha track as a draft; publishing is manual in Play Console. A green workflow reached no one.
- `run:` blocks take secrets through `env:`, never `${{ }}` spliced into the script text. Validate workflow edits with `actionlint`.
- `trunk` protection has `enforce_admins: false` on purpose: direct pushes to `trunk` skip PR CI, so the pre-push hook running `qualityGate` is the only net before they land; `uploadApk` still gates them after. Turning it on means every change needs a branch and PR. Change protection with a `PUT` of the whole object, never a PATCH. Check it: `gh api repos/emm3000/Just-Chill/branches/trunk/protection --jq '{checks: .required_status_checks.contexts, admins: .enforce_admins.enabled, linear: .required_linear_history.enabled, force: .allow_force_pushes.enabled}'`.
- The pre-push hook (`scripts/git-hooks/pre-push`, runs `qualityGate` only) is off after clone; opt in once with `git config --local core.hooksPath scripts/git-hooks`. Change the gate in the plugin, never in the hook.
