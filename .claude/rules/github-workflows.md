# CI, release and the gate

- `./gradlew qualityGate` is the gate, invoked by the three build workflows (`buildDev`, `uploadApk`, `uploadRelease`; `probeStorageRls` runs no Gradle). Its task list lives in the `qualityGate` task's own `description` in `build-logic/.../QualityGateConventionPlugin.kt`, next to the code that assembles it; read it there, never a prose copy elsewhere. `ConventionPluginTest`'s `GATE_TASKS` pins the per-module closure only, asserted against a one-module probe, so nothing root-level (`:build-logic:convention:test`), nothing a plugin contributes to one module (`verifySqlDelightMigration` on `:core:database`) and nothing `:androidApp` names for its flavors ever moves it. What the code cannot show: task-name matching never reaches an included build, so `:build-logic:convention:test` is named explicitly, as is `:androidApp`'s flavored test task, because its flavors live in its own build file; Android lint is not a gate task at all, and `uploadApk` names `lintDevDebug` in its own Gradle call instead; `compileReleaseKotlin` is named because nothing else type-checks a library module's release variant. `:androidApp` names its own two variant tasks in its build file, `testDevDebugUnitTest` and `compileProdReleaseKotlin`, because the plugin's `compileReleaseKotlin` never matches a flavored module and `assembleProdRelease` is not on the gate.
- Triggers. `buildDev` (PR to `trunk`): a `changes` job runs `git diff --name-only` against the base; the required check `quality-gate` is skipped (counted as passing) only when the PR touches `**/*.md`, `docs/**`, `.claude/**`, `scripts/justchill-*` or `.github/dependabot.yml` alone, and runs whenever `changes` did not succeed. It runs `qualityGate` alone, plus `assembleProdRelease` only when the PR touches a keep-rule file (`*.pro`) or `build-logic/convention/src/main/kotlin/com/emm/buildlogic/AndroidReleaseConventionPlugin.kt`. Everything else that can break the release — an AGP or R8 bump in `gradle/libs.versions.toml`, a `consumerProguardFiles` wiring in a library module, the prod flavor's own signing line in `androidApp/build.gradle.kts` — is caught by no R8 run on the PR itself, only by the `trunk` push that merges it and by `uploadRelease`. A PR's R8 run never protected on-device data, since the enum keep rules the app relies on are already absent and `assembleProdRelease` stays green when a keep rule points at a package that no longer exists. `uploadApk` (every `trunk` push): the full gate plus `lintDevDebug`, then `assembleDevDebug` and `assembleProdRelease`, both APKs distributed to Firebase App Distribution and both uploaded as artifacts; the `lint-report` artifact is uploaded here, not from `buildDev`; a newer push cancels the running one, so only the latest build reaches testers. No step is conditional: `workflow_dispatch` stays on the `on:` block to rerun the whole job by hand, never to gate a step. R8, resource shrinking and release lint therefore run on every `trunk` push, on a PR that touches the release wiring, and on `uploadRelease`. `uploadRelease` (tag `v*.*.*` or manual): gate, release lint, bundle, Play draft. Report upload paths are `**` globs, never module names.
- Branch protection is `strict: false`, so the `uploadApk` gate is the only net for semantic conflicts between PRs green on their own. Never drop it — its gate and its builds are separate concerns, and pausing the builds has never meant pausing the gate.
- Android lint left the PR path in #162. Before: the gate's unconditional floor on a diff touching no Kotlin was 117s of Gradle (`assembleDevDebug` 36s, `qualityGate` 81s on top, whole job 169s), measured in run [35287362996](https://github.com/emm3000/Just-Chill/actions/runs/35287362996); a local `--profile` attributed 52.7s of 88.9s of task time to lint alone (analyze + report). After: the floor on a diff touching no Kotlin is still unmeasured, but an ordinary one-file Kotlin PR now costs 88–106s of Gradle and 111–137s of job (#153's five baseline rounds below). #162's own PR run cannot supply the floor — editing `androidApp/build.gradle.kts` busts the configuration cache, so its 297s step is not comparable; take the number from a later `trunk` run, which also lost `assembleDevDebug`, so the two changes cannot be attributed separately. Measure this from CI only — those lint tasks go UP-TO-DATE unpredictably on a warm local run, which is #157's territory.
- The Crashlytics mapping upload runs only with `-Pjustchill.crashlyticsMappingUpload=true`, which `uploadApk` passes on `trunk` and `uploadRelease` on a release tag or a manual dispatch from `trunk`. PRs, Dependabot and local builds never upload.
- Caching. `uploadApk` on `trunk` is the only writer; `buildDev` and `uploadRelease` pass `cache-read-only: 'true'`. `uploadRelease` is read-only because it runs on a `v*.*.*` tag ref and GitHub scopes a cache entry written there to that tag, so no later run can restore it — writing only burns the repo's 10 GiB budget. `cache-encryption-key` is wired from the `GRADLE_ENCRYPTION_KEY` secret and the secret is set, but it does **not** persist the configuration cache and cannot: at the pinned setup-gradle SHA, project state (build-logic plus configuration cache) is stored only when the vendored caching library sees `DEVELOCITY_STORE_CONFIGURATION_CACHE=true` *and* a valid Develocity trial token and server URL, and the trial has a hard expiry date compiled in. Without Develocity every run prints `Calculating task graph as no cached configuration is available`, on `trunk` as on a PR — #153 measured it on both. The key stays wired because it costs nothing and is the prerequisite if Develocity ever arrives; an absent secret degrades, it never fails.
- Two cache levers were measured against `trunk` on 2026-09-19 (#153) and **neither was applied**; do not re-apply one without new numbers. Probe diff each time: one string in `:feature:report`. Baseline (`cache-read-only: 'true'`, no parallel) Gradle step 88s / 90s / 88s / 99s / 99s, runs [35419336666](https://github.com/emm3000/Just-Chill/actions/runs/35419336666), [35419491349](https://github.com/emm3000/Just-Chill/actions/runs/35419491349), [35419839464](https://github.com/emm3000/Just-Chill/actions/runs/35419839464), [35420076618](https://github.com/emm3000/Just-Chill/actions/runs/35420076618), [35420208317](https://github.com/emm3000/Just-Chill/actions/runs/35420208317). Letting a PR write its own cache scope (`cache-read-only: 'false'`): 67s then 98s, runs [35419338370](https://github.com/emm3000/Just-Chill/actions/runs/35419338370) and [35419493461](https://github.com/emm3000/Just-Chill/actions/runs/35419493461); the second run did restore its own `quality-gate[…]` entry instead of the cross-scope `distribute[…]` fallback, and still executed the identical `517 actionable tasks: 182 executed, 335 from cache`, while each run paid 12–16s of post-job save and wrote ~1.2 GB into a store already pinned at its 10 GiB ceiling. `org.gradle.parallel=true`: 83s / 74s / 89s / 102s / 106s, runs [35419340399](https://github.com/emm3000/Just-Chill/actions/runs/35419340399), [35419495748](https://github.com/emm3000/Just-Chill/actions/runs/35419495748), [35419841025](https://github.com/emm3000/Just-Chill/actions/runs/35419841025), [35420077966](https://github.com/emm3000/Just-Chill/actions/runs/35420077966), [35420210110](https://github.com/emm3000/Just-Chill/actions/runs/35420210110) — paired against the baseline round by round the sign flips three times out of five, mean 2s, no OOM. Measure paired rounds, never one run against another day's: an ordinary one-file Kotlin PR after #162 and the ADR 015 migration costs 88–106s of Gradle and 111–137s of job, and `trunk` landing between rounds moves it more than either lever does.
- Third-party actions are pinned to a commit SHA on purpose: they hold the signing and Play/Firebase credentials, and a floating `@v1` can be repointed upstream. Do not tidy them into tags; dependabot proposes bumps. GitHub's own `actions/*` stay on tags. The `github-actions` ecosystem scans `.github/workflows` and a *root* `action.yml` only, so `.github/dependabot.yml` lists `.github/actions/setup-android` under `directories` as well; drop it and that file's actions rot unseen.
- `versionName` is `git describe --tags --abbrev=0 --match "v[0-9]*"`. The filter is load-bearing (the repo carries non-release tags; builds once shipped `versionName = "pre-kmp"`), and `--abbrev=0` means it is always the bare tag, so `versionCode` is what names a build. Same filter in `/release`.
- A tag push does not ship. `uploadRelease.yml` uploads the AAB to the alpha track as a draft; publishing is manual in Play Console. A green workflow reached no one.
- `run:` blocks take secrets through `env:`, never `${{ }}` spliced into the script text. Validate workflow edits with `actionlint`.
- `trunk` protection has `enforce_admins: false` on purpose: direct pushes to `trunk` skip PR CI, and nothing runs locally before they land. `uploadApk` runs the full gate on every `trunk` push, so a bad direct push is caught after it lands, not before; with `required_linear_history` on and a single author, reverting it is cheap. Turning it on means every change needs a branch and PR. Change protection with a `PUT` of the whole object, never a PATCH. Check it: `gh api repos/emm3000/Just-Chill/branches/trunk/protection --jq '{checks: .required_status_checks.contexts, admins: .enforce_admins.enabled, linear: .required_linear_history.enabled, force: .allow_force_pushes.enabled}'`.
